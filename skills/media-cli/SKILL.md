# media-cli（@dkplus/media-cli）

媒体处理与 AI 生成 CLI。安装：`npm i -g @dkplus/media-cli`（需 Node >= 20）。

## 调用契约（AI 必读）

- 一律加 `--json`：stdout 输出单行 JSON 包络，直接 `JSON.parse`。
  - 成功：`{ "ok": true, "data": ..., "warnings": [...] }`
  - 失败：`{ "ok": false, "error": { "code", "message", "details" } }`
- 退出码：`0` 成功；`2` 用法错（E_MISSING_ARGUMENT / E_INVALID_OPTION）；`3` 执行错（E_CONFIG / E_MISSING_DEPENDENCY / E_PROVIDER_ERROR 等）。
- **兜底**：本文档可能滞后，用 `media-cli --json spec` 获取当前版本的完整命令树（name/options/source）——以 spec 为准。
- 非交互：永远不会挂起等待输入；缺必填参数会直接报 E_MISSING_ARGUMENT，不会 prompt。

## 坑位与输出语义

- `suno-gen`/`suno-sound` 默认**阻塞轮询直到完成并自动下载**（音频链接限时 1 小时，无需手动转存）；Suno 每次生成 **2 首**，批量语义见 `data.tracks[]` 与 `data.failed[]`；`--no-wait` 只提交返回 `{ taskIds }`；等待超时报 `E_PROVIDER_ERROR` 且 `details.taskIds` 可用 `suno-download --id` 恢复（积分已扣，务必恢复而不是重发）。
- `media-cutout` / `media-compress` / `media-watermark` 文件夹批量：部分失败不中断，检查 `data.failed[]`（file + reason）；全失败才报错。
- `media-to-pdf` 合并语义：一个目录 = **一个**多页 PDF（不像其他命令逐张出文件），页面顺序默认文件名自然序（`p2.jpg` 在 `p10.jpg` 前）；`--recursive` 时先按目录再按文件名分组排序。默认每页贴合该图尺寸（像素按 `--dpi` 换算成磅值，300dpi 下 3000px 宽 ≈ 720pt≈10 英寸）；要标准纸张用 `--page a4|letter`，横图默认 `--orientation auto` 自动出横页。页内图片默认重编码为 jpeg（`--quality 85`），**透明区域压成白底**；要保 alpha 用 `--image-format png`（体积明显变大）。EXIF 方向会先摆正再排页。
- `media-to-pdf` 失败语义与批量命令相反：默认**任一张图解码失败即整体报 `E_PROVIDER_ERROR`（`details.source=sharp`）且不落盘**，避免产出缺页的 PDF；确认可以丢页时再加 `--skip-broken`，跳过项计入 `data.skipped[]` 并附 `E_PARTIAL_INPUT` 警告（PDF 仍会生成）。`--output` 必须是 `.pdf` 文件路径且不能是已存在目录。
- `media-compress` 不 resize、不转格式；PNG 走无损优化（收益有限，大图建议压 jpg/webp）；重编码不比原图小时 `skipped: true` 且**不落盘**（原图永不变大）。EXIF 方向会摆正写进像素，orientation 5-8 的图输出宽高互换属正常（视觉分辨率不变）。
- `media-watermark` 整图斜角平铺水印：`--spacing` 是相邻水印间距 px，`--angle` 默认 30；字体由系统 fontconfig 解析，**字体不存在时静默回退默认字体不报错**；字号默认按最短边 1/24 自适应（14–160）；平铺数上限 20000，间距/字号过小报 `E_INVALID_OPTION` 提示增大 spacing。
- `media-face-cover` 每张贴一个实心白圆（人脸框内切圆 × `--scale`）：Apple Vision 本地离线检脸（macOS，首次运行 `swiftc` 编译并缓存）。实测一张真实 2048x2048 角色图检出 3 张正脸、背面人物**不误检**、EXIF 旋转变体坐标同样正确。**`--scale 1.2`（默认）能完全盖住正脸，但侧脸会露出眼睛——图里有转向/侧脸人物时把 `--scale` 提到 1.5–1.6**；漏检用 `--at x,y,r`（像素、左上原点，可重复）人工补，它与检测结果合并，且 Vision 不可用时只传 `--at` 照样出图。**检不到脸不是错误**：输出原图副本 + `E_NO_FACE_DETECTED` 警告 + exit 0，有没有真盖住要看 `data.covered` 而不是退出码。
- `media-grid-caption` 每格底部叠半透明黑条 + 白字、**不改变整图尺寸**；默认 `--font sans-serif` 实测能渲染真实中文字形（全分辨率目视复核，不是豆腐块）。定位优先级 `--cells` > `--cols/--rows` 等分 > 本地自动检测；本地检测**只认分隔线对齐的规则宫格**，倾斜/错位的分镜页会正确拒绝检测并走兜底版式（`data.layout="fallback-bottom"` + `E_GRID_NOT_DETECTED` 警告 + exit 0，字幕外扩到整图底部、输出图变高）。**格子重叠不再一律拒收**（`doubao-grid-locate` 的坐标放大回原图必然带几像素薄条，全拒等于打回兄弟命令的产物）：按 `--max-overlap`（默认 0.05，指重叠面积占**较小格**面积的比重；与 `doubao-grid-locate` 的 5% 修复窗口同值 = 「产出侧发得出来、消费侧就必收」的不变量）分级——≤ 阈值只发 `E_CELLS_OVERLAP` 警告并照常出图（exit 0，`data.minorOverlaps` 计数），> 阈值（实测真误检是 11%–33%）才 `E_INVALID_OPTION` exit 2；确认是刻意的分层版式就加 `--allow-overlap` 全放行。**报大重叠时不要重跑 `doubao-grid-locate`**（那份 JSON 就是它产的，重跑还是同一结果），出路只有 `--allow-overlap` / 编辑 JSON 改成共边 / 改用 `--cols/--rows`。格数与字幕条数不匹配只附 `E_PARTIAL_INPUT` 警告，不失败。**字号字段有一套口径**：`data.fontSize` 只是 `--font-size` 的回显（`null` = 自动档），实际画出来的字号看 `data.minFontSize`/`data.maxFontSize`（聚合区间，没画任何条时是 `null`）与 `data.fontSizePerCell`（仅 in-cell 版式，`[{index,fontSize}]` 每格真值）；兜底版式 `min==max` 且无 `fontSizePerCell`。每格字号优先级 `cells[].fontSize` > `--font-size` > 自动档。
- `doubao-grid-locate` 用豆包视觉模型给整页分镜/漫画输出每格像素矩形；**它的 `data` 就是 `media-grid-caption --cells` 能直接吃的 cells JSON**（统一 schema，可 `--output` 落盘、人工核对修改后再用，中间零转换）。送模型前按 `--max-side`（默认 1568）降采样并**统一重编码 JPEG q82**，透明 PNG 先压白底（`data.notes` 说明，`data.sent.encode` 记录编码）：实测真实 2048x2048 RGBA 页 data URI 8,737,762 → **397,995** 字符（瘦 95.4%；旧的「保留 PNG 无损」只瘦 9.2%）。**返回的坐标一律是原图像素**（`data.scale`/`data.sent` 记录这次缩放）。⚠️ **瘦身不降耗时**：同一页 `--max-side 512`（请求体再瘦 89.5%）与默认一样在 3 次 × 120s 全部 abort（累计 362.7s）——**视觉这条路径很慢（以分钟计）且快慢全在 provider 侧**，本命令超时默认因此是 300000ms（`--timeout` 可覆盖）。实测两轮真实 3x3 分镜页（面板倾斜、边界互相错开）：**S019 329.6s、S017 181.8s**（降采样改动后比原来更慢，不是更快）；一页返回 9 个位置正确的框、另一页只返回 **7** 个（模型把相邻两格合并，台词会被静默丢掉），返回 9 格那页还出现过两格重叠 628x24px。**所以框每次都必须肉眼核对后再用**：`--expected` 只是提示模型应有格数，与实际不符仅附 `E_CELL_COUNT_MISMATCH` 警告、不会失败。薄条重叠已在产出侧切齐（`data.overlapRepaired` + `E_CELL_OVERLAP_REPAIRED` 警告），大重叠则原样交给 `media-grid-caption` 分级（附 `E_CELLS_OVERLAP` 警告说明）。
- `media-compress-video` 重编码只保留**一条视频轨 + 一条音轨**（字幕、多音轨、章节丢弃，音轨统一转 AAC）；默认 mp4 + faststart（网页边下边播），`--codec hevc` 体积更小但慢且需 libx265；`--max-height` 仅缩小不放大；耗时与时长/分辨率成正比（超时 1 小时报 `E_PROVIDER_ERROR`）。
- `media-compress-audio` 有损格式默认保持原格式重压；wav/aiff 默认转 flac（无损缩小），flac→flac 通常 `skipped: true`。
- A/V 压缩（video/audio）结果不比原文件小时 `skipped: true` 且**回滚不落盘**；**拒绝原地覆盖**（`--output` 与输入相同/输出目录=输入目录报 `E_INVALID_OPTION`，A/V 是流式写文件，与图片的缓冲写不同）。
- `image-gen` 多账号池自动轮换重试（401/403/429/5xx），无需调用方处理；400 类参数错误不轮换直接报 `E_PROVIDER_ERROR`。
- `image-gen --ref` 按扩展名推断 mimetype 传给 Azure，仅支持 jpg/jpeg/png/webp；其他格式（heic、bin 等）本地即报 `E_INVALID_OPTION`（退出码 2），不发请求。HEIC 先转 jpg 再喂。**Azure 的参考图不能给 URL**（实测 2026-10-19）：`images/edits` 的 `image[]` 收到字符串报 400 `expected a file, but got a string instead`，`images/generations` 连参考图字段都没有（`image/images/image_url/image_urls/input_image(s)/reference_image(s)/ref_images/input_reference/init_image/condition_image` 全部 `Unknown parameter`），classic 面与 `/openai/v1` 面行为一致、chat 与 responses 面对 gpt-image-2 一律 `The requested operation is unsupported.`——要 URL 只能自己先下载到本地。这与 BananaRouter 相反（见下）。
- `--moderation`（Azure 与 BananaRouter 都支持，枚举只有 `auto|low`，本仓库默认 `low`）只放宽模型侧的额外过滤，**不是关掉内容审核**：Azure 的内容安全层仍会拦并报 `ResponsibleAIPolicyViolation`，2025-04-01-preview 的官方参考页还没把这个字段写进去（文档滞后，别据文档判断不支持）。
- `image-gen --size` 非标比例可直接传对应 WxH，不限于 1024/1536 三档（如 4:3 传 `1536x1152` 实测可出图）。
- `agnes-image` 是**同步**接口（`POST {base}/v1/images/generations`，没有任务轮询）：实测 1K 文生图约 10s、4K 约 20–28s、一次图生图编辑 20–158s，**超时预算别按秒级设**（`AGNES_TIMEOUT_MS` 默认 360000）。`--size` 是**档位**（`1K/2K/3K/4K`）或 `WIDTHxHEIGHT`，默认 4K：档位锁的是**面积**（`1K`+`1:1`→1024x1024、`2K`+`1:1`→2048x2048、`4K`+`1:1`→4096x4096、`4K`+`21:9`→6272x2688）；**显式 `WxH` 会被静默降采样**（实测请求 2048x1152 实收 1312x736）——所以要最大像素就传 `--size 4K`，传 WxH 拿不到更多像素。`data.size` 永远报真实解码像素；只有传显式 `WxH` 时才做「请求值 vs 实测」比对并附 `E_SIZE_MISMATCH` 警告（档位模式的期望像素本地推不出来，故不比对）。
- `agnes-image --ref` **可多张（实测上限 6）且本地文件直接可用**：本地路径被读成 base64 data URI 内联进请求，**不需要先 `tencent-cos-upload`**（实测 4096x4096 / 10.5MB 的 PNG 内联成 14MB data URI 照样接受）；http(s) URL 原样透传。这与 `modelscope-image-gen`/`-fast` 的 `--ref`（只收公网 URL）是关键差异；ModelScope 侧现在只有 `modelscope-image-edit` 同样吃本地文件（实测上限 4 张）。传了 `--ref` 即走图生图，`data.mode="i2i"`，可用结果 URL 的路径段 `/images/t2i/…` vs `/images/i2i/…` 交叉验证真走了编辑。prompt 上限 **10000 字符**（本地预检，超限 `E_INVALID_OPTION` 且不发网络）。
- MiniMax 三条命令的坑：① `GET /v1/models` 只列文本模型，**不代表语音/音乐/视频不可用**，别拿它判定能力；② 语音/音乐的音频在 `data.audio` 里是 **hex** 不是 base64（插件已解码落盘，也兼容 URL 下载），且**不要自行传 `audio_setting`**（实测极易 400）；③ 音乐是同步接口，全曲响应体可达 ~10MB、耗时 >30s，`--timeout` 默认 600000；④ 视频走 **v2**（`POST /v2/video_generation` + `GET /v2/query/video_generation/{id}`），只有 H3/H3-Max 两档，duration/resolution 按型号分别校验；`ratio` 按场景分档——t2v 必填具体比例且不许 `adaptive`、**i2v 恒为 `adaptive`（传具体比例被静默忽略）**、r2v 默认 `adaptive` 可覆盖；实测 **H3 5s/768P 约 118s、H3-Max 同档约 10s**，赶时间用 Max；超时后任务可能仍在跑（`details.taskId`，可用 `DELETE /v2/video_generation/{task_id}` 删）；⑤ 成败先看 `base_resp.status_code` / `task.error`，别只看 HTTP 200——**提交返回 200 + task_id 不代表参数合法**，服务端把很多校验推到执行期；⑥ 实测三条「提交期不校验」：图片每边 [256,5760] 与宽高比 [0.4,2.5]（1×1 的图照样建任务，随后才 failed）、`--last-frame` 缺 `--first-frame`、未知顶层字段一律静默忽略——插件都已在本地拦；⑦ `middle_frame` 这个 role **不存在**（互斥报错的文案里出现了它，别照抄），`extra`（即 `--prompt-expansion`）与 H3 不兼容、只有 H3-Max 收，枚举 `disabled|balanced|quality`（文档特别警告不要传 `balance`）；⑧ 请求体总大小 ≤64MB，base64 放大约 4/3，大文件改传公网 URL 或 `mm_file://{file_id}`；⑨ 再生走 **v2** `POST /v2/video_regeneration`，把 H3 的 **768P** 成片升 **2K**（`resolution` 必填且当前**只支持 2K**、`ratio`/`duration` 跟随源视频不传），入参 `--source-task-id`（须当前账号、7 天内、`succeeded`、768P；服务端回填 prompt，**禁再传 `--prompt`**）与 `--base-video`（`content` 里恰好一个 `role=base_video`，须配 `--prompt`）**二选一**，查询复用同一 `GET /v2/query/video_generation/{id}`；**不是通用超分**，外部视频（手机拍摄/其他模型）会被拒；官方请求体 `model` 是 `MiniMax-H3`，第三方网关叫 `MiniMax-H3-Regeneration`（`--model`/`MINIMAX_VIDEO_REGEN_MODEL` 覆盖）。
- `minimax-image` 走 MiniMax 官方同步接口：文生图 `POST /v1/images/generations`，带 `--ref` 切到 `POST /v1/images/edits`（JSON `images:[{image_url}]`，本地文件内联 data URI；参考图 1–16 张、单张 ≤64MiB、每边 [128,8192]、长短边比 ≤4:1、请求体 ≤64MiB）。实测 2026-11-12：1024x1024 **8.9s** / 2048x2048 **8.5s** / 4096x4096 **13.1s**（`response_format=url`，落盘 0.37/0.99/4.2MB），图生图 **10.0s**。默认 `1024x1024` + jpeg（provider 默认是 auto/4K；要最大档传 `--area 4K` 或 `--size 4096x4096`）。**显式 WxH 时不能再传 `aspect_ratio`/`area`（连 auto 都 400）**；`--disable-prompt-enhanced` 必须给显式比例（WxH 或 auto + `X:Y`）。**HTTP 200 也要逐项看 `data[].error`**（部分图失败仍 200，1026/1027 为内容安全）；结果 URL 24h 过期，命令拿到即下载。
- BananaRouter `banana-image-gen`：token **按模型授权**（当前只开 `gpt-image-2`，换模型先在控制台开通）；默认 `quality=low`、`moderation=low`、`1024x1024`、`jpeg`。**非法尺寸网关不报错而是静默降级成 2880x2880**，所以本地按「每边 ≤3840、16 的倍数、长短边比 ≤3:1、总像素 655360–8294400」预检并报 `E_INVALID_OPTION`（`--size auto` 合法）；`--ref` 多图且**本地路径与 http(s) URL 可混传**（实测 2026-10-19：URL / data URI / 纯 base64 / `{"image_url":…}` 四种形态网关都真消费）——全本地走 multipart `image[]`（仅 jpg/jpeg/png/webp），一旦含 URL 就整体改走 JSON `images`、本地文件内联成 data URI；网关侧 URL 限制：单图 ≤20MB、下载超时 30s、单请求内最多 5 并发、私有/保留 IP 被 SSRF 拒、允许 jpeg/png/gif/webp/bmp。**带 scheme 的非 http(s) 入参在本地就拒**——网关对这类字符串不走协议分支而当 base64 解码，报 `illegal base64 data` 会把排查引到错方向。参考图的下载校验**先于**参数枚举校验，所以拿 edits 探 moderation 之类的枚举值探不出来，要用 generations 探。实测延迟 65–159s 抖动大（超时默认 300000ms），`data.size` 是 sharp 解出的真实像素，请求值不符时附 `E_SIZE_MISMATCH` 警告。
- BananaRouter **`output_format` 也会被静默忽略**（2026-10-18 实测，单样本）：同 prompt、`2880x2880`、请求 `jpeg`，`quality=low` 那次实收 **PNG**（12.35MB），`quality=high` 那次才是 JPEG（2.25MB）——HTTP 200、`size` 照实回、**没有任何警告**。判格式只看 `data.format`（sharp 真值）和 `data.bytes`。体积口径顺带实测：2880² 同图 **PNG 是 JPEG 的 6–9 倍**（12–15MB vs 1.3–2.4MB），`quality` 档对体积基本不参与换算，「高质量=文件大」在这条路上不成立。
- `agnes-image` 的编辑（i2i）通道会间歇回 **HTTP 503 `image queue is full`**，1–3s 内快速失败。这是 provider 侧容量，**与你的 key 和 payload 体积都无关**（已专项验证），命令在**同一把 key 上原地退避重试**，次数受 `AGNES_MAX_RETRIES`（默认 6）、总预算受 `AGNES_TIMEOUT_MS`；重试过程写 stderr，调用方只看最终结果。文生图侧 3 路并发实测全部成功。

- 豆包（doubao）转写：**模型不返回逐句时间戳**，长音频按 silencedetect 静音点切段（默认 30s/段，硬上限 1.5 倍），SRT 段边界精确、段内各行按字数比例估算，多段结果会附 `E_TIMELINE_APPROXIMATE` 警告——要精确时间轴改用 `media-transcribe`。整段一次请求在 ~180s 会超时，命令内部已自动切段并发（默认 4），调用方无需干预；180s 音频实测约 9s 完成。`401/403 → E_CONFIG`（不重试），`429/5xx/超时`自动重试 2 次（400ms/1200ms 退避）；单段失败报 `E_PROVIDER_ERROR` 且 `details.segment/window` 指出是第几段（整条命令失败，不产出半成品字幕）。`--format txt` 只出纯文本、无 `data.cues`。
- `doubao-music-analysis` 音乐理解：输出 JSON 音乐描述（isMusic/hasVocals/genre/emotion/tempo.bpm/key/instruments/structure 分段/videoFit 视频适用场景与剪辑建议/highlight 记忆点/oneLineSummary），`data.analysis` 与落盘文件同构。**分析比转写慢**（推理密集，45s 音乐约 50s、6 分钟约 2–3 分钟），≤240s 整曲单请求，更长曲子自动按 `--segment-seconds`（默认 120s）切段并发再合并，长曲分段边界会有轻微机械感属预期。模型时间戳是估算：structure 未覆盖到音频结尾时附 `E_TIMELINE_APPROXIMATE` 警告；输入疑似非音乐时附 `E_NOT_MUSIC` 警告（不失败，仍输出尽力描述）。文件夹批量逐文件容错（`data.failed[]`），`--recursive` 递归；模型实测能区分一次请求里的多段音频（本命令长曲切段即基于此能力）。转写与分析共用同一组 doubao 环境变量。
- `modelscope-image-gen` 走 ModelScope API-Inference 网关，参数名以官方文档 AIGC 生图表为准：`--size` 传 **`WxH` 字符串**（网关不认 `width`/`height`，实测传这两个会被静默忽略出 760x1280；`928*1664` 星号格式被拒），`--steps` [1,50]（官方文档写 [1,100]，但 **`Qwen/Qwen-Image-2.1` 与 `Qwen/Qwen-Image-Edit` 的网关都只收 [1,50]**，提交期 400 原文 `steps must be in [1,50]`；本地已按实测的 50 收紧，`--steps 80` 直接 `E_INVALID_OPTION`，不再白跑一次提交去吃 400）、`--guidance` [1,20]（**下限已从 1.5 放宽到 1**，因为 Turbo 官方 CFG=1）、`--seed` [0,2^31-1]、`--negative-prompt`、**prompt 上限 4000 字符**（gen 与 fast 共用同一条本地预检）；**尺寸上限以实测为准：网关按每边 [64, 2048] 校验**（文档表写的 1664 不是硬限；超界提交期直接 400，如 `width must be integer in [64,2048]`，不吃额度），`2048x2048` 实测真出 2048×2048。官方 7 个比例用 `--ratio 1:1|4:3|3:4|3:2|2:3|16:9|9:16`（映射到网关可用的最大档，与 `--size` 二选一；`--ratio 16:9` 实测真出 2048×1152）；注意 Qwen 仓库推荐的 2400/2528/2752 长边是本地 diffusers 档位，经网关会被拒。可用模型清单见 https://www.modelscope.cn/aigc/models 。链路是提交 + 轮询 `{base}/v1/tasks/{id}`（`task_status` 取 `SUCCEED`/`FAILED`，图在顶层 `output_images[]`）；**提交响应会提前回 `SUCCEED` 但任务还在跑**，客户端已按「无图且有 task_id 就继续轮询」处理。结果图 URL 下载不带 apikey，输出永不含 key。`data.size` 是**真实解码像素**，与请求不一致时附 `E_SIZE_MISMATCH` 警告（说明该部署按自身档位调整了）。超时/失败报 `E_PROVIDER_ERROR` 且 `details.taskId` 可排查；失败原因已摊进 `error.message`（网关错误载荷是 `errors:{message,request_id}` 对象或 `errors[]` 数组也会被挖出第一句文本，不会显示 `[object Object]`），另给 `details.requestId`（找 provider 排查）与 `details.raw`（原始 JSON 截断兜底）。
- `tencent-cos-upload` 只上传**单个文件**（目录 → `E_INVALID_OPTION`，不存在 → `E_MISSING_ARGUMENT`），对象永久保留：不写过期的元数据、不驻留进程计时。默认对象名把非 ASCII 字符折叠成 `-`（key 直接进公网 URL，不做二次编码），`--key` 拒绝绝对路径与 `..`。`data.url` = 池 `CDN_PURGE_URL_<ENV>` 的 origin + `/` + key，与桶的 COS 默认域名无关——若该域名前置 CDN 且对象未回源，URL 可能延迟可见。
- `MODELSCOPE_KEY_POOL` 多 token 池（并发/额度按 **key** 计：实测同 key 已有任务在跑时再提交直接 429 `We have to rate limit you for model …`，一把 key 无法并行）。策略：提交起点随机、401/403/429/5xx/网络错误换下一把，400 类参数错误不轮换，全池失败报 `E_PROVIDER_ERROR` 带逐把 `details.attempts`；**异步任务只属于提交它的账号，所以轮询固定沿用成功的那把 key**，轮询期撞 429 用同 key 续等而不是判失败（避免作废已付费的生成）；`data.keyIndex` 回显消耗了池里第几把（只报下标，输出永不含 key 原文）。要真并行出多张就并发起多个进程，池会自行分摊。
- `modelscope-image-gen --ref <urls...>` 走图生图/多图参考编辑（Qwen-Image-2.1 官方卡片：文生图与编辑统一模型，单次**上限 10 张**参考图；网关侧参数是 `image_url`，一张传字符串、多张传 URL 数组）。**只接受 http(s) 公网 URL**，本地路径不做隐式上传——先 `tencent-cos-upload --file a.png` 拿 `data.url` 再喂 `--ref`（要直接把本地文件当参考图，改用 `modelscope-image-edit`，它实测吃 data URI）；结果 `data.refUrls` 按传入顺序回显。实测单图编辑生效（构图/果柄/光照保持，材质按 prompt 替换）；实测多图 `--ref 图1 图2` 两张都被消费（用带独有特征的两张参考图做判据：黄苹果+黑五角星、紫肉+方籽西瓜，出图两处特征同时复现）。响应 `sourceUrl` 里的 `aigc/text-to-image/` 路径只是存储目录名，不代表没走编辑。
- `modelscope-image-edit` 是同一链路的「编辑档」（默认 `Qwen/Qwen-Image-Edit`，`MODELSCOPE_EDIT_MODEL` 或 `--model` 可覆盖），**选它的理由就是参考图可以直接给本地文件**：`--ref ./a.png https://cdn/b.png` 混传也行，插件按扩展名（png/jpg/jpeg/webp）读成 `data:image/<mime>;base64,` 内联进 `image_url`，**不需要先 `tencent-cos-upload`**。实测依据（2026-10-15）：同一张源图分别以公网 URL 与 data URI 提交，data URI 那次出图的服装、徽记、五官都来自该参考图，证明网关**真的消费** data URI 而非静默忽略（`modelscope-image-gen`/`-fast` 没验证过这一点，那两条仍只收 URL）。硬限全部是网关实测原文，超限本地预检 `E_INVALID_OPTION` 且**一次网络都不发**：参考图**最多 4 张**（`image_url count 9 exceeds maximum limit of 4`）、prompt **4000 字符**（`invalid prompt or prompt length more than 4000`，按字符不按字节）、每边 **[64,2048]**（`width must be integer in [64,2048]`，`1024*1024` 星号格式被拒 `size format should be WxH`）、`--steps` **[1,50]**（`steps must be in [1,50]`）、`--guidance` **[1.0,20.0]**（`guidance must be in [1.0,20.0]`）。默认 `--size 2048x2048`、默认**不发** steps/guidance（Edit 的官方推荐档待实测，不替用户猜）；**没有 `--ratio`**（编辑要跟参考图保持构图，传了按未知选项 exit 2）；`--ref` **不是必填**，不传时网关照样接受提交并出图（退化为文生图，实测）。输出前缀 `modelscope-edit-`，`data` 与兄弟命令同形并多给 `data.refCount`；**data URI 绝不回显原文**，`data.refUrls` 里压成 `data:<mime>;base64,<N> bytes`（N 是解码字节数）。缺文件 → `E_MISSING_ARGUMENT`，未实测的扩展名（gif/bmp…）与 `file://`/`ftp://`/手传的 `data:` URI → `E_INVALID_OPTION`，都不发网络。key 池轮换、pinned-key 轮询、`scrub`、真实像素 `E_SIZE_MISMATCH` 警告、任务记录约 10 分钟过期（拿到就立即下载）全部沿用同一条实现。⚠️ **限流真实形态**：同一把 key 3 路并发提交实测全部成功，但**连续快发会撞按模型计的限流**，原文 `We have to rate limit you for model Qwen/Qwen-Image-Edit. If you need higher limits, please consider other (commercial) API providers.`——这就是要按 key 计的 429，现有池轮换已经处理，批量提交请拉开间隔或多进程。**仍未实测、别当事实说**：`seed` 的真实可用区间（探测时被限流打断，现仍只按文档 [0,2^31-1] 校验）、4 张参考图同框的**组合质量**（只验证过 4 张能提交并产出图像，没评估各图特征是否都被采纳）、Edit 端到端耗时（未计时）。
- `modelscope-image-fast` 是同一链路的「默认值即最快最大」档：默认 `Qwen/Qwen-Image-2.1-Turbo` + `--steps 8` + `--guidance 1` + `--size 2048x2048`，**实测 2048x2048 端到端 37.1s**（PIL 复核为真实像素）；**同一把 key 4 路并发提交实测全部成功**（与 `Qwen/Qwen-Image-2.1` 的按 key 单并发不同，所以批量出图优先用 fast，单并发那条只约束 gen）。选项集与 gen 一致（`--ratio`/`--seed`/`--negative-prompt`/`--ref` ≤10 张只收公网 URL），只有默认值与输出前缀 `modelscope-fast-` 不同；模型名可用 `MODELSCOPE_FAST_MODEL` 或每次 `--model` 覆盖。**要快/要最大用 fast，要指定非 Turbo 模型用 gen。**
- `modelscope-image-h3` 是 ModelScope 网关上的 MiniMax-H3-Image 档（模型卡：固定 6 steps / guidance 1、无 negative_prompt，故命令不暴露这些选项）。**实测 2026-11-12：网关对 `MiniMax/MiniMax-H3-Image` 的提交稳定返回 HTTP 400 `submit failed with code: 40000`（两把池 key 均如此，偶尔夹 `user queue is full` / 429），模型页 `SupportApiInference=false` 这次是真的；同时网关每边硬上限仍是 2048，4096x4096 在本地就被拒。** 图生图沿用网关的 `image_url`（`/v1/images/edits` 在网关是 404，`image_url` 参数本身会被网关识别并尝试下载），但模型未开放，编辑形态未实测；4K 出图请改用 `minimax-image`。
- ⚠️ **ModelScope 任务记录约 10 分钟后过期**：之后再轮询同一 task_id 会回 `task not found`。命令拿到就立刻下载，这是设计而非巧合——**不要事后再补拉结果 URL**，过期只能重新提交。
- 生图引擎选择：默认（含图生图、参考图一致性）一律走 Azure `image-gen`；`modelscope-image-gen` 是备选引擎，**只在用户点名 ModelScope / 千问 / Qwen-Image 时使用，永不作为 Azure 失败后的自动兜底**，反向同理。同样规则套在新引擎上：`agnes-image` 只在用户点名 Agnes、或明确要 **4K/最大像素**、或想**直接拿本地文件当参考图**（免上传 CDN）时用它；`modelscope-image-fast` 只在点名「快速/turbo/最快出图」或批量并发出图时用它；`modelscope-image-edit` 只在点名「ModelScope 编辑/改图/Qwen-Image-Edit/局部重绘」，或**参考图只有本地文件、又不想先上 CDN**（且接受 ModelScope）时用它——它是 ModelScope 三条命令里唯一吃本地文件的，`gen`/`fast` 仍只收公网 URL；`agnes-video` 是目前唯一的生视频命令（但实际出片待实测，调用前先告诉用户这点）。
- 错误码语义：`E_CONFIG` 配置缺失/非法 → 检查 env；`E_MISSING_DEPENDENCY` 外部二进制缺失 → `details.hint` 有安装提示（`media-face-cover` 缺 `swiftc` 即此类）；`E_PROVIDER_ERROR` 远端/进程失败 → `details.source` 标明来源（ffmpeg/whisper/vision/azure/suno/modelscope/agnes/tencent-cos）。**警告码不影响退出码**（`E_SIZE_MISMATCH` / `E_NO_FACE_DETECTED` / `E_GRID_NOT_DETECTED` / `E_CELL_COUNT_MISMATCH` / `E_CELLS_OVERLAP` / `E_CELL_OVERLAP_REPAIRED` / `E_PARTIAL_INPUT` / `E_TEXT_TRUNCATED` 只出现在 `warnings[]`），AI 调用方要同时读 `ok` 与 `warnings` 才判得准。
